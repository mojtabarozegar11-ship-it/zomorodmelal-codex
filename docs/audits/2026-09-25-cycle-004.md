## Deep audit finding

### Location

- `django_project/apps/ai/content_agent.py`
- `django_project/apps/ai/content_agent_models.py`

### REASON

The content publication workflow had an owner approval flag on the publication itself, but publication approval/publication did not re-check the upstream approval state of the ContentBrief and ContentChannel.

The repository already models both upstream approval fields:

- `ContentBrief.owner_approved`
- `ContentChannel.owner_approved`

The workflow therefore had a demonstrable policy-chain gap: a publication could reach its publication-level approval gate without requiring those upstream objects to have been owner-approved.

### CHANGE

The publication approval path now requires:

1. ContentBrief owner approval.
2. ContentChannel owner approval.
3. Publication owner approval by the owner.

The final `publish()` execution boundary independently re-checks the ContentBrief and ContentChannel approval flags before allowing publication.

This is a defense-in-depth change: the final execution boundary does not trust an earlier UI/workflow state.
