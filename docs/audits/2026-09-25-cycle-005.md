# Cycle 005 — Site Foundation Hardening

Date: 2026-09-25

## REASON
The active Django site already contains the shared template and static foundation, but the site contract tests only verified URL resolution. That left regressions in shared metadata, core static assets, and homepage rendering able to pass unnoticed.

## CHANGE
- Hardened `django_project/templates/base.html` with:
  - viewport-fit mobile metadata
  - robots metadata hook
  - Open Graph metadata hooks
  - canonical URL
  - keyboard-accessible skip link
  - explicit main-content landmark
- Hardened `django_project/static/site/main.css` with:
  - visible keyboard focus skip link
  - reduced-motion support
- Expanded `django_project/apps/site/tests.py` to verify:
  - core static assets exist
  - homepage renders successfully
  - canonical metadata is present
  - main content landmark is present
  - core homepage sections remain present

## SECURITY / HTTPS AUDIT
Repository evidence confirms:
- `SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")`
- HTTPS redirect is enabled by default when `DEBUG=False`
- secure session and CSRF cookies are enabled by default when `DEBUG=False`
- both canonical HTTPS hostnames are present in `ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS`
- Passenger imports the canonical `config.wsgi.application`
- production deployment remains manually gated by workflow dispatch and owner-approval inputs

A focused security contract test was added at:
`django_project/config/test_security_foundation.py`

This verifies the repository-level HTTPS/host/security contract. It does not prove that a live client can reach TCP/443 or that a reverse proxy/certificate is healthy.
